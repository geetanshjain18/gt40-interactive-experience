## Current environment

- The post-ignition scene is a hand-built, late-1960s Le Mans pit-garage set: a cutaway cyclorama with an open central garage portal, a distant pit apron and barrier, petrol-painted rear wall sections, steel portal supports and ceiling beams, muted practical strips, a small `FORD / 24 HEURES DU MANS / PIT 6` sign, tire stacks, a trolley, workbench, oil drums and an extinguisher.

- The same single Canvas and loaded GT40 instance are retained. Camera paths, audio controls, page text, and native scroll are unchanged.

## Grounding diagnosis and correction

- The prior loader used `Box3.setFromObject(scene)` with its default transformed-AABB bounds. Rotated wheel bounds expanded the reported vertical minimum to `-1.350235`, even though the actual lowest tire vertices were near `-1.016929` in model space; this lifted the tires from the floor.
- The loader now uses precise vertex bounds, finds the four `GT40_Tyre_Rubber` meshes under `GT40_WheelFL/FR/BL/BR`, fits a small longitudinal pitch from their contact minima, then positions the four-point average contact plane at world `y=0`. No GLB vertices or wheel transforms are edited.
- Browser measurement after normalization reports each wheel bottom within `0.00035` scene units of `y=0` on desktop and mobile. The measured root scale is `0.486320` for the existing 4.8-unit target length.

## Limits and next checks

- The garage is intentionally procedural low-poly geometry, not a photogrammetric or archival reconstruction; no external textures or branded artwork were added.
- Dynamic shadow-map quality and sustained frame rate were not benchmarked. The contact shadows are static soft decals; monitor frame time on lower-end devices if more animated lights or props are added.
- If the GLB changes, rerun `node scripts/diagnose-gt40-ground.mjs`, `node scripts/garage-ground-qa.mjs`, `node scripts/final-gt40-qa.mjs`, and `npm run build` before accepting new tire alignment.

# Headlight raycast correction (2026-10-07)

- Root cause: hit testing raycast only the interactive parts, so a wheel mesh behind the headlight could win when the lamp's transparent cover was not treated as a visible occluder. A first full-scene pass also exposed an opaque `Plane014` in front of the lamp target because transparent registered headlight covers had been omitted from the visibility list.
- Correction: cache visible model meshes as occluders and always include registered visible component meshes even when their material is transparent. Raycasting now chooses the nearest actual visible model surface, and returns a component only when that surface is an active mapped hotspot for the current camera frame.
- Chromium QA probed both image-right and image-left lamp areas at x=1020/420, y=565. First intersections now resolve to `GT40_HeadLightCover` / `headlights` at distance ~3.12; `Cylinder041`/`Cylinder042` wheel meshes are behind at ~3.66 and are not selected. The rendered hover card is `Headlight Assemblies`; frame-specific chapter-list tests still pass and browser errors are empty. Report and updated screenshots are in `artifacts/component-explorer-20261007/report.json` and `desktop-hover-headlight.png`.
- `npm run build` passes TypeScript and Vite; the existing >500 kB bundle warning remains. Reversible pre-edit files are in `artifacts/headlight-raycast-fix-before-20261007-131044/`.
